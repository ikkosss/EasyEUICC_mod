# Почему пересобранный EasyEUICC не видит профили в слотах SIM

## Коротко

Съёмная карта eSIM сама решает, какому приложению отдать доступ к своему апплету ISD-R. Решение
принимается по **SHA-1 отпечатку сертификата подписи APK** (правила ARA-M на карте, механизм
GlobalPlatform Secure Element Access Control, который в Android обслуживает системная служба
`com.android.se`). Карта, купленная для официального EasyEUICC, содержит отпечаток официального
ключа и отклоняет любую сборку, подписанную другим ключом.

| | SHA-1 сертификата |
| --- | --- |
| Официальный EasyEUICC 1.7.2 (`EasyEUICC-v1.7.2.apk`) | `2A2FA878BC7C3354C2CF82935A5945A3EDAE4AFA` |
| Наша сборка (`signing/easyeuicc-ru.jks`) | `D3060AD2C34684E17E80B6AE586FD1AE80C60F92` |

Первый отпечаток прямо указан в README проекта как хеш, который производители карт должны внести
в ARA-M, чтобы карта работала с официальными сборками EasyEUICC. Наш отпечаток в карте не прописан,
поэтому `Session.openLogicalChannel(ISD-R)` завершается `SecurityException`, канал не открывается,
и приложение честно показывает «не найдено съёмных карт eSIM» — при полностью рабочем устройстве и
рабочей карте.

Из-за этого же проверка совместимости проходит успешно: она проверяет устройство, а не карту, и
специально считает `SecurityException` признаком того, что OMAPI на телефоне работает.

## Что было проверено

Сборка из этого репозитория функционально совпадает с официальным APK — различаются только
подпись, локализация и строка версии:

* содержимое ZIP: те же 1106 записей, лишних и отсутствующих файлов нет;
* по CRC различаются ровно пять записей: `AndroidManifest.xml` (версия), `resources.arsc`
  (переводы), `res/YN.xml` (`locale_config`), `classes2.dex` (переводы + нумерация слотов с 1),
  `META-INF/version-control-info.textproto`;
* все восемь нативных библиотек (`lib/*/liblpac-jni.so`, `lib/*/libdatastore_shared_counter.so`)
  **побайтово равны** официальным, то есть `lpac`, NDK и флаги сборки подобраны верно.

Значит, ни `lpac`, ни версии подмодулей, ни локализация к проблеме отношения не имеют.

## Что делать

1. **Официальный APK.** Для доступа к карте в слоте SIM нужна подпись официального ключа. Русский
   перевод в официальный релиз может попасть только через upstream (gitea.angry.im/PeterCxy/OpenEUICC).
2. **USB-считыватель CCID.** Через USB обе сборки работают независимо от ARA-M: карта вынимается из
   телефона и вставляется в считыватель, приложение видит её как отдельный «слот».
3. **Карта, которая знает наш отпечаток.** Если у карты можно настроить ARA-M (или производитель
   готов внести хеш), добавьте `D3060AD2C34684E17E80B6AE586FD1AE80C60F92`. Отпечаток текущей
   сборки всегда виден в приложении: «Настройки» → «ARA-M SHA-1» (нажатие копирует в буфер) и на
   экране-заглушке в блоке диагностики.
4. **Root.** Привилегированный вариант OpenEUICC работает в обход ARA-M, так как использует
   `TelephonyManager` вместо OMAPI. Он устанавливается как системное приложение модулем Magisk
   (`dist/OpenEUICC-ru-magisk.zip`), после установки в «Настройках» нужно включить
   «Использовать TelephonyManager для съёмных SIM», иначе съёмные карты по-прежнему пойдут через
   OMAPI.

## Диагностика в приложении

Экран «не найдено съёмных карт eSIM» теперь сам объясняет причину для каждого слота:

* `карта не обнаружена` — в слоте нет карты (`Reader.isSecureElementPresent == false`);
* `карта отказала в доступе: в её правилах ARA-M нет подписи этой сборки` — ровно тот случай,
  который описан выше;
* `карта есть, но апплет ISD-R не найден (это не eUICC)` — обычная SIM-карта либо нестандартный AID
  (список AID можно дополнить в настройках разработчика);
* `доступ есть (ISD-R ...)` — карта пускает приложение, и если профили всё равно не появились,
  причину надо искать в `lpac` (включите подробный журнал в настройках).
